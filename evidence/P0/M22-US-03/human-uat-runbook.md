# M22-US-03 独立送礼真实老板桌面/手机 UAT

状态：`PENDING_EXTERNAL`

本手册只定义 `AT-GIFT2-004` 尚缺的真人交互证据。不得由 Codex、Bot 或自动探针代签，也不得把 `guild-recovery-uat.json` 的自动恢复结果当作真人桌面/手机验收。

## 前置条件

- 仅在 `BUSINESS_ENV=SANDBOX` 的测试 Guild 执行，使用一名真实、非 Bot 的老板测试账号。
- 同 Guild 已有至少两名 `ACTIVE` 陪玩、一个有效礼物和一个可制造余额不足的礼物；老板已绑定内部 CAT 账户。
- `gift_entry_channel_id` 指向测试频道，Bot 具备 View、Send、Embed Links、Read History 与 Manage Messages；频道只有一张已置顶的送礼入口卡。
- `GIFT_CONTINUATION_SIGNING_SECRET` 在重启前后保持不变且至少 32 字符；同一 token 不运行第二套 Bot Gateway 会话。
- 执行前记录老板钱包、活动预留、礼物请求、客服任务与 Outbox 基线。除明确最终确认场景外，其他步骤不得产生业务写入。

## UAT-1：桌面端公开最短路径

1. 桌面端点击公共卡“送礼物”，确认回复为 ephemeral，公共频道没有余额、陪玩目录或个人选择。
2. 选择一名陪玩，再选择一个余额充足的礼物。
3. 确认页核对陪玩、礼物和 CAT 金额；点击“公开赠送”。
4. 确认成功页明确“已预留、尚未正式扣除”，且只创建一个礼物请求、一个活动预留和一个客服任务。

记录：从公共入口到最终确认的完整录屏、点击数、request ID、礼物 public ID 和预留 ID。

## UAT-2：手机端匿名路径

1. 手机端重新打开公共卡，选择另一名陪玩和礼物。
2. 在同一确认页直接点击“匿名赠送”；匿名不得增加单独页面或强制留言。
3. 确认客户私密成功页显示匿名模式，公共入口及其他频道没有客户身份或余额。

记录：手机完整录屏、点击数、request ID、礼物 public ID；匿名审批后多角色播报与内部对账归 `M22-US-05`。

## UAT-3：余额不足、充值续接与旧组件恢复

1. 选择余额不足的礼物，确认页面显示差额、充值帮助、刷新余额和返回，且礼物、预留、客服任务均零新增。
2. 由有权限员工按现有 SANDBOX 充值流程补足 CAT；老板点击原页面“刷新余额”，不重新选择陪玩或礼物。
3. 在最终确认页面停止 Bot，使用同一签名密钥重启；在 30 分钟有效期内点击重启前的“刷新余额”或最终确认按钮。
4. 确认旧组件可继续或安全回读最新事实，不依赖进程内 Map，不重复预留。

记录：余额不足前后对账、充值记录、Bot 停止/启动时间、旧组件响应、request ID 和最终唯一业务事实。

## UAT-4：入口删卡与启动恢复

1. 记录当前入口 message ID 并删除该消息，不点击任何送礼确认。
2. 重启 Bot，确认测试频道自动出现一个新的置顶入口 message ID。
3. 连续再重启一次，确认复用新 message ID，频道仍恰好一张入口卡，礼物、钱包和预留零变化。

自动探针已验证同类 REST 恢复与持久投影，但本步骤仍需真人在桌面和手机确认卡片可见、按钮可点且布局无截断。

## 通过与签署

必须同时保存：桌面与手机录屏、关键截图、点击数、全部 request ID、旧/新 message ID、钱包及业务事实前后对账，以及老板、运营和 QA 的姓名、时间与结论。任一余额公开、跨 Guild 陪玩、重复预留、匿名身份泄露、旧组件重复写入或删卡不恢复均判定失败。
