# M22-US-04 客服辅助送礼模式 B 真实 Guild UAT

状态：`PENDING_EXTERNAL`

本手册只收集 `AT-GIFT2-005` 的真实 Discord、真实人员与真实 TOTP 证据。不得由 Codex、Bot、自动探针或测试替身代签；任何截图、日志或录屏不得包含 TOTP、MFA secret、恢复码或完整敏感凭证。

## 前置条件

- 仅在 `BUSINESS_ENV=SANDBOX` 测试 Guild 执行，准备一名真实老板、一名具备内部 `gift.assist` 的 L1-L4 客服、一名无该权限员工和至少一名同 Guild `ACTIVE` 陪玩。
- 客服已通过现有安全入口登记本人 TOTP；Discord Role 仅用于命令可见性，API 权限事实必须来自当前内部员工状态、scope 与 `permissions_version`。
- 准备一个余额充足礼物、一个余额不足礼物；记录老板钱包、活动预留、礼物请求、客服任务与审计基线。
- 老板在指定测试频道发送明确授权客服辅助送礼的消息。只保留 message ID、channel ID、作者绑定和测试意图说明，不复制消息正文到业务事实。

## UAT-1：桌面端公开最短路径

1. 客服在桌面端右键老板本人授权消息，选择“应用 → 协助此老板送礼”。
2. 确认私密页面显示正确老板余额；选择陪玩、礼物和“公开赠送并验证”。
3. 在最终 Modal 填写授权原因和客服本人当前六位 TOTP。
4. 确认只创建一个礼物请求、一个 ACTIVE 预留和一个 `GIFT_REVIEW` 任务；老板是付款人，客服是执行者，资金仍是“已预留、尚未正式扣除”。

记录：完整录屏、点击数、request ID、challenge ID、礼物 public ID、预留 ID、任务 ID及前后对账；遮盖输入 TOTP 的画面。

## UAT-2：手机端匿名路径

1. 使用新的老板授权消息与新 challenge，在手机端完成陪玩、礼物选择。
2. 选择“匿名赠送并验证”，填写原因和当前 TOTP。
3. 确认客服私密结果为匿名；后续陪玩/公开投影只显示“匿名老板”，不得包含老板 mention、昵称、Discord ID、头像、订单号或私密频道。
4. 内部受限对账仍能分别追踪老板付款人与客服执行者。

记录：手机录屏、匿名前后多角色截图、request ID 与内部对账截图；外部画面不得出现真实老板身份。

## UAT-3：拒绝路径与零业务写入

分别用独立 challenge 验证：无 `gift.assist` 员工、非客户/Bot 消息、跨 Guild 绑定、余额不足、错误 TOTP、第五次错误、十分钟过期、客服权限版本变化。每次记录错误码与 request ID，并证明礼物、预留、任务均零新增。错误 TOTP 只允许记录失败计数，不得出现在日志、审计或错误文本。

## UAT-4：单次消费与并发重放

1. 对同一 challenge 同时提交两次最终确认，随后再重放一次成功交互。
2. 确认最多一笔预留、一条礼物请求、一个任务和一次成功审计；其他请求返回已消费或幂等结果。
3. 核对 `availableMinor = ledgerBalanceMinor - reservedMinor` 且不为负，客服执行者和老板付款人归属不交换。

## 通过与签署

必须保存桌面/手机证据、全部 request ID、业务事实前后对账，以及老板、客服、运营和 QA 的姓名、时间与结论。任一越权、错误 TOTP 产生业务写入、重复预留、TOTP 泄露、匿名身份泄露或付款人/执行者混淆均判定失败。
