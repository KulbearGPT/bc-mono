## 2. 产品原则

1. **工作优先**：当前任务先于历史统计；班次控件紧凑但始终可达。
2. **先理解再认领**：可见任务在认领前返回 task-scoped 最小只读摘要，不授予完整订单或写权限。
3. **服务端决定业务顺序**：OVERDUE 优先，PENDING 按最早截止，其余按创建时间和 ID 稳定排序；浏览器只展示。
4. **链接失败关闭**：Discord Guild 或频道缺一时返回 `null`，隐藏动作并说明不可用，绝不拼出 `/channels//`。
5. **人类语言在前，技术事实可追溯**：公开编号、展示名、中文状态、相对/精确时间、阻塞和下一动作在主区；UUID、原因码、minor units 和审计元数据默认折叠。
6. **不扩大 P0**：不新增 CRM、聊天归档、排班、可配置 SLA、实时推送、批量处理、复杂工作流或客户端业务规则。

## 3. Story 切分

### M14-US-01 — 客服工作台体验合同与 RED 基线（DONE）

同步主规格、backlog、OpenAPI、交互映射、验收、TODO 和镜像；以合同测试固定边界。此 Story 不包含运行时代码。

### M14-US-02 — 安全任务分诊投影与 Discord 深链（4–6 人日）

- `listStaffTasks/getStaffTask` 返回 `StaffTaskTriageSummary` 与 `StaffTaskLinks`。
- 摘要只含客服分诊所需白名单字段；完整订单权限不变。
- 深链只由 API 使用可信 Guild/频道事实生成。
- 服务端稳定分诊顺序及跨页测试。

完成门禁：AT-SUX-002/003/004；API、数据库、字段白名单、L1-L4、跨 Guild 回归通过。

### M14-US-03 — 首屏任务队列与认领前只读上下文（5–8 人日）

- 页面顺序调整为紧凑班次状态 → 任务队列 → 汇总。
- 任务卡展示对象、原因、时间压力、负责人、下一动作和有效深链。
- 认领前详情只消费 M14-US-02 的最小摘要。
- 空、错、缺链接、键盘及 375/768/桌面状态完整。

完成门禁：AT-SUX-001/003/004；Dashboard 测试、typecheck、production build 和浏览器 E2E 通过。

### M14-US-04 — 人性化订单信息层级与可行动指标跳转（4–6 人日）

- 订单列表/详情优先公开编号、展示名、项目、中文状态、金额、相对与精确时间、阻塞和下一动作。
- 技术字段默认折叠；高权限操作与客服摘要分区。
- 待处理、超时、进行中指标进入同 scope 的服务端筛选结果。
- 保留 M13 CARD/TABLE parity，不改变订单状态机、资金或 capability。

完成门禁：AT-SUX-005/006；路由恢复、权限、金额、时间、筛选和详情回归通过。

### M14-US-05 — RBAC、可访问性与真实员工 UAT（3–5 人日）

覆盖 L1-L4、已认领/未认领/超时/缺频道、375/768/桌面、键盘和读屏；由真实客服在当前业务 Guild 完成从发现任务到进入订单现场的闭环。真实员工 UAT 只覆盖当前业务 Guild，不要求准备第二个真实 Guild；跨 Guild 隔离继续由 API/数据库自动化回归证明。

完成门禁：AT-SUX-001..007、全量回归、生产构建、真实员工 UAT 与产品/客服签署。
